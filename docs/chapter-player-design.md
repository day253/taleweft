# TaleWeft 章节编辑器交互设计 · v0.1

## 目标

让有声剧、广播剧和有声小说的创作者，像读小说、改文章一样处理声音作品。章节正文是主要工作区；角色参数就地展开，声音素材通过正文标注和底部时间轴操作。Agent 后续使用同一组编辑命令。

这一版用于验证操作方式。没有接入音频生成、云端存储或真实 Agent。

## 一次典型操作

1. 粘贴长文本或上传 TXT / Markdown，先看章节、角色和片段的拆分预览，再应用；可撤销回原作品。
2. 在左侧切换章节。在正文直接改字，或用段落上方的角色下拉框指定演播者。
3. 点片段的设置按钮，就地展开参数卡：角色、情绪、语速、停顿和模型选择。阅读模式收起编辑控件。
4. 音效作为短标签出现在对应段落下方。点击标签调整名称、偏移和音量。
5. 背景音乐用连续的淡色边框包围覆盖的正文，上方显示音乐名称。选择起止段落时，文字长度变化会更新音乐时长。
6. 在下方人声、音效、配乐、环境四轨中选中或移动素材。拖动靠近段落起点时吸附；正文标注同步更新。
7. 展开“生成记录 Debug”，查看这段声音当时使用的文字、人声、提示词、参数与输出。编辑当前正文后，历史快照保持原样并提示差异。

## 界面与编辑边界

### 左侧导航

章节、角色、音效、配乐、环境采用同一个资源面板，降低切换成本。章节标题、作品名、作品类型直接可改。角色卡展开人声描述、语气和语速；从资源库点击加号绑定当前片段，也可拖入时间轴。

当前角色编辑覆盖声音设定；完整的角色生平、跨章人物关系和角色版本留待后续扩展。

### 正文工作区

每个片段拥有稳定 ID，显示角色、表达方式、估算起点和正文。文本使用 Tiptap；片段设置借鉴 ComfyUI 节点内部的表单编辑。阅读模式以连续正文为主；编辑模式保留必要的声音标记。

当前以段落为最小操作单元，支持直接编辑和上下移动。任意字符范围的拆分、合并、跨段选择与精确范围 Agent 修改尚待实现。不能把现有“当前片段”修改声称为逐字选区修改。

### 时间轴和播放器

时间轴选择人声片段会定位正文。音效、音乐、环境片段可拖动，右边缘可调整长度；方向键每次移动 0.5 秒。锚点有两种：绑定文本片段，或固定的时间位置。手动拖动离开吸附范围后变为时间位置；吸附到另一段则重新绑定。

配乐可额外绑定结束段落；拖动或直接裁切后解除结束段落绑定，保留当时长度。当前边界最小为 0.5 秒。

播放器当前采用浏览器系统朗读，并以估算时间驱动播放头。音效、音乐、环境以及波形是编排示例，不参与真实混音；轨道静音仅为编排状态演示。系统朗读与估算播放头不会精确同步。后续以解码后的实际音频时长和 Web Audio 调度替换。

## Audio Debug：每个输出都能解释来源

Debug 属于音频片段的核心能力。真正接入生成后，每次请求创建不可变的 GenerationRun；可编辑的 Segment 只引用当前选择的 Take。修改文字或角色声音不会改写旧 Run。

每份记录需要包含：

- 来源：作品、章节、片段 ID、文档修订号、父版本和生成时间。
- 输入：完整文本快照、角色名称和声音快照、提示词、模型能力类型。
- 模型：供应商、模型 ID 与版本、适配器版本、原始请求参数；只有模型实际支持时才记录 seed。
- 参考素材：素材 ID、内容哈希、媒体类型、裁切区间与版本，不能只保存可能过期的 URL。
- 输出：音频素材 ID、哈希、格式、采样率、声道、真实时长，以及对应的 Take。
- 过程：请求 ID、耗时、成功或失败状态、结构化错误、重试来源、实际后处理步骤。

正文中显示“当前文本与所选音频版本不一致”。Debug 面板支持输入与当前内容比较、历史 Take 试听比较、复制可脱敏的生成配方，以及用旧快照重建新请求。重做不会覆盖旧输出。同样的输入不承诺获得完全相同的波形，取决于供应商的模型版本和确定性能力。

分享配方时排除 API 密钥、授权头和签名 URL。需要让其他机器复现时，导出配方 JSON 与引用素材清单；音频 metadata 可保存 manifest ID，但不是唯一存储位置。

**当前原型**只对内置示例片段展示一份明确标识的设计快照，支持查看 / 复制 JSON 和恢复本段参数。没有真实生成文件、多版本试听、失败日志或重试请求。新导入片段显示“没有生成记录”。

## 状态、持久化与后续库结构

当前采用 Next.js App Router、React、TypeScript、Tiptap、Zustand、IndexedDB（idb-keyval）与 Tailwind/CSS。正文、角色、音轨使用同一份文档状态；选中状态和展开状态与文档内容分离。撤销最多保留 30 个文档快照，连续输入合并；撤销历史只存在于当前会话。

项目内容和当前章节保存到当前浏览器、当前地址的 IndexedDB。localhost 与局域网 IP 是不同的存储来源；不同设备也不自动同步。导出 JSON 是备份导出，当前没有 JSON 项目恢复入口。接口密钥不进入前端文档。

未来拆库建议：

- core：文档 schema、命令、稳定 ID、锚点计算、修订和撤销协议，不依赖 React。
- editor-react：正文渲染、角色选择、片段卡、声音范围标注。
- player：实际音频时钟、多轨调度、裁切、混音与波形。
- provenance：生成配方、不可变运行记录、Take 历史、差异与复现清单。
- adapters：供应商能力声明、参数表单与生成请求适配。
- playground：本仓库当前 Next.js 应用，作为可运行示例。

先把编辑命令和交互验证清楚，再拆 package，避免早期过度设计。Mastra 后续负责规划、调用和生成编排；UI 无需知道某个供应商的内部 SDK。

## 局部 Agent 修改协议

Agent 使用与人工编辑相同的命令入口。请求显式指定作品修订、章节和片段范围；返回待应用 patch。UI 显示影响范围与变更预览，用户应用后可一次撤销。修订不匹配时拒绝旧建议并重新预览，防止覆盖用户的新改动。

原型仅支持情绪、语速和停顿的本地规则演示；长文本拆分按章节标题及“角色：台词”识别。自由改写、语义识别与音频生成尚未实现。

## 本次验证

- 类型检查、生产构建通过；4 项数据层测试覆盖文字重排后的声音锚点、配乐范围随正文时长变化、导入内容和局部 patch 边界。
- 浏览器验证正文修改、刷新恢复、历史快照不被覆盖、参数恢复。
- 浏览器拖动门铃至另一段：标签同步移动，吸附绑定更新，撤销恢复。
- 浏览器验证长文本拆分预览、应用和撤销；局部参数预览、应用和撤销。
- 浏览器验证播放头推进及暂停；实际音质与准确同步不在这一版验证范围内。
